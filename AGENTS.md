# Agent guidance

Read [docs/project-guidance.md](docs/project-guidance.md) for research and operating requirements before changes; use [docs/README.md](docs/README.md) for category guides and verification, and [plan.md](plan.md) for milestones.

- Standing authorization: after each completed feature or fix, run relevant checks, commit the change with related tests/docs, and push to the current branch’s configured upstream without asking again. Stage only that change; preserve unrelated user work. Do not force-push, rewrite published history, or amend unrelated commits. Report commit/push failures and unpushed commit IDs.
- Use Colab for training. Prefer CPU for the current small-network research workload (user direction, 2026-10-15); consider the cheapest suitable GPU only after profiling, and use A100 only when explicitly requested or its benefit is demonstrated. Complete lower-credit preflight first. Existing authorization covers a cumulative 150-unit project ceiling, teardown by 130 units, and a two-hour initial allocation deadline. Count setup, idle time, downloads, failures, and retries; preserve the ledger across runtimes. Stop only task-owned sessions.
- Reuse the existing official Colab CLI installation. Reinstallation/upgrades require an explicit request or an identified compatibility problem explained before changes.
- Concurrent Colab sessions are authorized (user direction, 2026-10-16), with configurable concurrency and suitable CPU/GPU hardware; there is no fixed two-session or CPU-only limit. All sessions share the same cumulative 150-unit project ceiling and 130-unit teardown threshold. Use centralized aggregate metering to avoid double-counting overlapping account debits, budget projected operations across all active sessions, persist every owned session ID, enforce each allocation's deadline, and stop/verify every owned session on failure or interruption. Never stop unrelated sessions. Hardware choices still require workload profiling and cost justification; do not interpret concurrency authorization as a request to allocate expensive GPUs by default.
- Match Colab’s actual default kernel Python before dependency changes or training. Do not install an older interpreter or preserve outdated pins through compatibility workarounds.
- Offline simulation is the default. Training/backtesting does not authorize broker orders; live trading requires an explicit user request. Use a persistent local/server process for live-data inference and paper orchestration.
